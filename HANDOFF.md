# HANDOFF — SOP / WI / OPL Studio

> เอกสารนี้เขียนให้ AI หรือโปรแกรมคนถัดไปอ่าน (ภาษาไทยอยู่ท้ายไฟล์)
> Read this first. It explains what exists, how it works, and what is still missing.

## 1. What the app is

A web app that turns raw inputs (Excel, Word .docx, PDF, photos/scans, typed text) into a
finished, print-ready **SOP / WI / OPL** document rendered on a virtual A4/A3 page, and exported
as a high-resolution image (PNG), PDF/print, or a ZIP bundle (image + Excel + backup JSON).

AI does the heavy lifting: split text into 3-10 steps, shorten wording, flag cautions,
recommend PPE, pick document type + template + accent colour.

## 2. Stack (do not change casually)

- **TanStack Start v1** (React 19 + Vite 7, SSR/prerender, Cloudflare Worker runtime for server code)
- **Tailwind CSS v4** via `src/styles.css` (native `@theme`, no tailwind.config.js)
- **Lovable Cloud = Supabase** for storage (`@supabase/supabase-js`), PostgREST access
- **Lovable AI Gateway** (`https://ai.gateway.lovable.dev/v1`) for the AI conversion
- Router is TanStack Router: `src/router.tsx`, `src/routes/__root.tsx`, file-based routes.
  Never add react-router-dom / Next-style layouts. `src/routeTree.gen.ts` is generated — never edit.

## 4. Data model

Table `public.documents`:

| column | type |
| --- | --- |
| id | uuid pk |
| owner_key | text (per-browser UUID from localStorage) |
| title | text |
| doc_type | text (`SOP` \| `WI` \| `OPL`) |
| template | text (one of the 12 template ids) |
| content | jsonb — full `DocContent` (title, docNo, rev, steps[], ppe[], warnings[], keyPoints[], decorations[], color, font, paper, orientation, logo, QR) |
| created_at / updated_at | timestamptz |

Security model (deliberate): the table has **RLS enabled with no public policies**; every read/write
goes through server functions using `supabaseAdmin`, and each query is filtered by `owner_key`.
There is intentionally **no login**. Do not add a public RLS policy — that would expose every
document. Do not remove the `owner_key` filter.

## 5. AI conversion contract

`POST /api/ai-convert` (public server route, body `{ text, docType, files[] }`):
- images and PDFs are forwarded to the model as multimodal input; Word/Excel are converted to
  text in the browser first (see `src/lib/extract.ts`)
- calls `POST https://ai.gateway.lovable.dev/v1/responses` with
  `model: "openai/gpt-6-astra"`, header `Lovable-API-Key: <LOVABLE_API_KEY>`,
  `X-Lovable-AIG-SDK: fetch`, streamed + buffered server-side, then `JSON.parse` of the model output
- the system prompt (in `src/routes/api/ai-convert.ts`) is strict: it enumerates allowed
  template ids and PPE ids and demands JSON-only output. If you add a template, add its id to
  `TEMPLATE_IDS` in that file **and** to `TEMPLATES` in `src/lib/doc-model.ts`, otherwise the AI
  will never pick it.
- Note: the user originally asked for "Gemini 3 Flash via Emergent LLM Key"; the shipped build uses
  the workspace AI Gateway with `openai/gpt-6-astra` (same capability: reads images and PDFs).
  Keep this unless the user explicitly asks to switch.

## 6. How to run

```sh
npm i            # or: bun
npm run dev      # Vite dev server on :8080
npm run build    # production build (also catches Worker-runtime incompatibilities)
```

Environment (`.env`, generated by Lovable Cloud — do not hand-edit unless moving the project):
`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`
(and the non-VITE mirrors). `LOVABLE_API_KEY` is injected server-side by the platform; it is not
in `.env` and is not available outside Lovable.

## 7. Known limitations / honest gaps

1. **No accounts.** Documents belong to the browser that made them (localStorage owner key).
   Clearing browser data or switching devices loses access. A login/share system is the biggest gap.
2. **No crop / no image editing.** Photos are compressed in the browser and stored inline as
   data URLs inside `content`, which makes rows large. A storage bucket would be the proper fix.
3. **No version history / revision approval flow**, no audit trail, no "who changed what".
4. **No multi-language output** (UI is Thai only), no bilingual export.
5. **No search/tagging/folder** for the document list; a growing list is just a flat grid.
6. Strictness was relaxed (`noUnusedLocals`/`noUnusedParameters` off in `tsconfig.json`) to get the
   build green. Restore them once unused code is cleaned up.
7. Export fidelity depends on `html-to-image`; complex decorations/fonts can raster differently.
8. No tests yet (`vitest` is configured, `vitest.config.ts` exists, nothing meaningful written).

## 8. Suggested next work (in value order)

1. Optional login (email + Google) with a `user_id` linked to existing `owner_key` rows, so old
   documents migrate to the account. Keep the no-login path working as a fallback.
2. Move step images to a storage bucket; keep only URLs in `content`.
3. PDF export with selectable text (not just raster), plus a real page-break/second-page mode for
   long SOPs.
4. Template authoring: make a template a data object (layout + tokens) instead of a `switch` branch,
   so new designs can be added without touching `DocPage.tsx`.
5. Batch convert (drop 20 files → 20 documents) and a duplicate/"base on this" flow.
6. Version history + revision diff + approve/sign-off state.
7. Localisation and a bilingual (TH/EN) export toggle.
8. Tests for `doc-model` + a smoke test of `/api/ai-convert` against the gateway.

## 9. Rules to respect while editing

- Every new `public` table needs `GRANT`s in the same migration as `CREATE TABLE`, plus RLS.
- Roles (if you ever add them) go in a separate `user_roles` table + a `security definer`
  `has_role()` helper — never a column on profiles.
- Server-only code: `*.server.ts` or `src/server/` are import-blocked from client bundles; put
  client-imported `createServerFn` modules in `src/lib/` (that is the pattern used here).
- Read `process.env[...]` **inside** `.handler()`/handlers, never at module scope.
- Keep all `@import` rules at the top of `src/styles.css`; load web fonts with a `<link>` in
  `src/routes/__root.tsx`, never `@import` a remote URL in CSS.
- Never edit `src/integrations/supabase/*` (auto-generated) or `src/routeTree.gen.ts`.
- Verify with `/tmp/observability/build-errors.log` and a real browser run before claiming a fix.

AI แยกขั้นตอน สรุปข้อความ แนะนำ PPE ข้อควรระวัง และเลือกเทมเพลตให้เอง มี 12 เทมเพลต
